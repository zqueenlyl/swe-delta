# swe-delta

AI 时代软件工程整条链路上的做法：需求怎样孵化、知识怎样维护，以及编码、测试、上线、观测。只写关键环节和措施，不写具体实现。

让 AI 围绕有证据的现状提出变更，通过确认、交付和核验，持续更新可信的系统知识。

三角洲是上游的东西沉积下来的地方，Δ 是变更。需求在上游孵化，确认后记成对现状的变更，上线后沉成事实。

## 核心关系

- **知识单元**描述系统知识，是组织、引用和核验的基本对象。
- **变更集 Δ**描述需求引起的变化，作用于一个或多个知识单元，不是另一份全量知识库。
- **成熟度**区分未确认的想法、已承诺的变更和已生效的事实；事实层叠加未交付的承诺变更，得到未来视图。

知识按限界上下文组织，L0–L3 描述知识的结构分类，I/C/F 描述成熟度及使用方式。结构与状态是两个正交维度；变更流程把二者用于一次需求的完整处理，不是第三种知识分层。

## 阅读入口

- **第一次阅读**：先看本页，再看[贯穿案例](change-workflow.md#case-study)，了解一条需求怎样走完闭环。
- **建立或查阅知识库**：读知识组织，再按成熟度模型选取可引用的视图。
- **处理一条新需求**：按变更流程推进，需要判定结构与门禁时回查对应模型。

当前重点是知识组织、需求孵化与变更闭环。编码、测试、上线和观测先保留必要的衔接与核验措施，不展开具体工具、存储、变更集格式或实现方案。
